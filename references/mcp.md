# MCP 首次连接与恢复

客户端在用户电脑运行；Skill 是操作说明，不会自动为宿主注册工具。用户安装客户端或提供密钥后，仍需按宿主的实际连接机制完成配置和验证。

## 1. 引导取得用户授权的配置

引导用户打开 **知影 → 设置 → MCP**，启用 MCP，点击“复制密钥”，或使用界面中的“交给 AI 配置”/HTTP 配置复制功能。普通本机连接不需要打开“允许其他设备连接”。不要主动轮换密钥、读取磁盘凭据库或调用管理 API 取出所有设置与真实密钥。

优先让用户在宿主受保护的配置字段中填入密钥。若用户选择发送给当前 Agent，先用一句话说明这是允许访问知影知识库和发起任务的连接凭据，发送后会进入当前 Agent 服务；用户明确选择此方式后再接收并配置。不要回显、截图、打印完整密钥，或写入 Skill、仓库、公开文档、命令历史和普通日志。模型 API Key 与此密钥不同，不要求一起提供。

## 2. 匹配当前宿主的真实格式

优先 Streamable HTTP：

- 展示名称：`DeepVid MCP`
- 配置标识：`deepvid`（保持小写无空格；宿主支持独立展示名时使用上面的名称）
- URL：`http://127.0.0.1:54977/mcp`
- Header：`Authorization: Bearer <用户提供的 MCP 密钥>`
- 旧 SSE 仅在宿主确实需要时使用：`http://127.0.0.1:54977/mcp/sse`

下面是知影界面提供的通用 JSON 示例，**不是所有宿主都可直接粘贴的统一格式**：

```json
{
  "mcpServers": {
    "deepvid": {
      "type": "http",
      "url": "http://127.0.0.1:54977/mcp",
      "headers": {
        "Authorization": "Bearer <用户提供的 MCP 密钥>"
      }
    }
  }
}
```

确定当前 Agent 产品、版本、连接传输、真实配置位置和安全密钥存储方式；使用当前宿主的配置工具、内置说明或官方文档。不要猜测 Codex/Cursor/Claude 等的配置文件、JSON/TOML 格式、命令参数或热加载能力。只配置用户当前使用的宿主，不批量修改其他 AI 工具。

修改前说明目标宿主、配置范围，以及它会取得知影本地数据/任务访问权限，取得同意。优先用户级私密配置，不将密钥写进项目级可提交文件；保留现有其他服务和设置，按需备份并限制文件访问。验证修改后的结构与权限，不输出包含密钥的 diff。若宿主支持凭据存储/环境变量引用，使用其真实支持的方式，不发明插值语法。

若 HTTP 不受支持而需 stdio，使用客户端复制的 **实际可执行命令与参数**，不要给最终用户配置 `python -m backend.mcp.stdio` 这种源码开发命令。stdio 通道与 HTTP 鉴权不同；即使 stdio 能独立读取历史，新精读仍依赖运行中的桌面客户端。不要把 `DeepVid.exe` 或 GUI `.app` 猜成 stdio 入口。

## 3. 连接验证

通过宿主的 MCP 重连/刷新机制执行握手与工具发现，确认实际出现 `search_notes`、`get_note`、`create_digest`、`get_digest_status` 等工具。必要时使用与用户目标相关的只读检索确认可调用；空知识库也可以成功连接。

无法动态加载时，明确告诉用户配置已保存，但需要刷新工具、重开会话或重启宿主（按该宿主要求）。此时不要说“已连接，可以开始”，也不要在当前会话假装调用不存在的工具。给出原始视频来源和当前进度，方便用户恢复后继续。

若宿主有合法的本机 HTTP 执行能力，但不能在本轮刷新 MCP，可在用户已授权连接和任务范围内，通过上述同一 MCP HTTP 端点进行 JSON-RPC 协商和调用；先 `initialize`、`notifications/initialized`、`tools/list`，再按实际 schema 执行 `tools/call`。必须明确这是当前会话的临时调用方式，不能声称原生工具已加载；不要绕过 MCP 改用管理/内部任务 API。

## 4. 按错误恢复

| 现象 | 下一步 |
| --- | --- |
| 连接被拒绝/服务不在 | 回到客户端启动检查；不直接重新下载 |
| HTTP 401 | 请用户检查/重新复制 MCP 密钥；不自动生成或撤销 |
| HTTP 403 | 检查是否确在同机、MCP 是否启用、宿主是否受网络权限限制；不默认开放 LAN |
| 工具列表为空/缺少新工具 | 检查宿主刷新状态与已安装客户端能力，不根据仓库源码推断已安装版本 |
| 模型配置未就绪 | 按 `digest.md` 引导模型配置；不是 MCP 密钥错误 |

远程网页 Agent/云执行器一般不能访问用户回环地址。遇到这种情况，解释需要具备本机访问能力的 Agent 或宿主正式支持的本地连接机制；不要上传密钥至 Agensi、开启公网隧道、改监听地址或开放防火墙来凑通连接。
