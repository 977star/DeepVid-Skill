# 模型准备与视频精读

## 模型设置：只补齐缺项

阅读历史笔记不需要发起转写或新模型调用。新精读沿用知影已保存的配置；不要为“检测就绪”发起无关视频任务，也不要读取整个设置文件或输出真实 API Key。当前 MCP 没有专门的无副作用模型就绪工具：可让用户确认设置，随后在已同意的真实任务中根据服务端前置检查处理缺项。

首次引导位置为 **设置 → 模型配置**，分两部分解释：

1. **语音识别（ASR）**：把音频转换为文字。用户可选在线提供商，或本地 SenseVoice 离线模型。本地模型需首次在客户端点击下载，约 155 MB 下载、约 230 MB 磁盘（以当前界面实际大小为准）；确认用户愿意下载后操作/引导，等到下载完成并选用。不是每个安装包都已内置权重。在线方式由用户在客户端填对应服务的 API Key。
2. **笔记大模型（LLM）**：将文字整理为图文笔记。在客户端选择自己已有的服务，填入 API Key 并选择模型。DeepSeek、SiliconFlow、Gemini、知影在线等以当前客户端可选项为准。支持时使用界面的模型列表/连接测试，不编造默认模型名或“测试成功”。

不要混淆“本地语音识别”和“本地大模型”。前者就绪不代表后者可用，也不代表整条流程免费。Ollama、LM Studio 与自定义 OpenAI 兼容大模型受当前客户端权益限制；只有用户已有可用权限且明确选择时才引导，并检查本地服务已启动、模型已下载、名称/地址正确。不要默认安装这些额外软件，不声称所有免费用户都支持全本地处理。Skill 不主动推广购买；选项受限时说明事实，帮助选择当前可用的模型。

API Key 优先让用户自己填在知影，不要求发到聊天。说明在线转写/笔记生成会把相应内容交给所选提供商，可能按其规则计费；不承诺与外部 Agent 的订阅共享额度，也不把免费 Skill 等同于免费模型服务。

补齐后保留原视频，首次明确询问是否开始本次精读。若实际调用仍提示缺配置，引用返回中的具体缺项，指导修正后再重试一次；失败后停下并给可执行的排查下一步，不循环改设置或反复提交。

## 接受来源与确认范围

- 网络视频/音频 URL：保留原始链接；有已知笔记时先 `get_note_by_url(url, detail="summary")`，命中则按需要读取，不强制刷新。登录、平台限制、媒体获取失败时给出服务端原因；不要承诺所有链接可用。
- 本机文件：使用知影所在电脑可读的音视频绝对路径，先确认文件存在；聊天附件/远程容器里的路径不等于客户端能访问，必要时请用户保存到本机或用宿主支持的传输方式。
- 本机目录：在授权范围内只枚举候选媒体，不读无关文件，跳过符号链接以免超出范围。用户未说明递归/全部处理时列出数量与简要清单，询问处理哪些、是否包含子目录。无法访问本机就让用户选文件或提供可访问的路径。
- 当前 `create_digest` 接收单个 URL/文件路径，`batch_create_digest` 接收 `sources` 数组，二者都不接收目录作为“自动遍历”参数。

多视频先检查真实工具与服务端能力。用户已具备批量能力时用 `batch_create_digest(sources=...)`；受限时说明限制，可在用户确认后使用服务端允许的单视频逐一精读，不承诺批量并发、不用自行并发调用模拟受限功能。文件很多时先确认规模和可能费用。

## 执行与观察

以当前连接的 `tools/list` schema 为准；已安装的客户端可能早于源码，不能假定全部工具都存在。

| 工具 | 用途与常用参数 |
| --- | --- |
| `search_notes` | `query`、`limit`：查历史笔记，相关查询即可 |
| `get_note_by_url` | `url`、`detail="summary"`：按原始 URL 查重 |
| `create_digest` | `source`、`force_refresh=false`：提交单条新任务；强制重新精读需用户明确要求 |
| `get_digest_status` | `task_id`（或 `source`）、`result_detail="none"/"summary"`：检查运行状态 |
| `wait_digest` | 如可用，`task_id`、`timeout_seconds=30`、`result_detail="summary"`：等待终态，单次最长 60 秒 |
| `get_note` | `note_id`、`detail="summary"/"insights"/"full"`：读取真实笔记 |
| `query_note` | 如可用，`note_id`、`query`：查找证据与时间戳 |

提交后记录返回的 Task ID。工具可能返回文本或结构化结果，解析真实状态；已有笔记直接返回时不虚构新任务 ID。优先有限等待；没有 `wait_digest` 时约每 10–20 秒查一次，避免高频轮询。等待期间简短告知当前阶段，不连续长时间静默阻塞。

遵循当前会话允许的执行时长；无法继续等待就交付 Task ID、当前状态和下一次查询方法，说明知影保持运行即可继续处理。不要自行创建监控/通知自动化，不声称稍后一定会主动回来。失败、取消、权益拒绝是不同结果；失败后不给出“精读完成”，不自动强制刷新重跑。只有连接短暂中断且尚未拿到 Task ID 时，先按来源查状态/已有结果，避免重复提交。

完成后取得 Note ID。用户要求“精读视频”“帮我看这个视频”“查看图文笔记”时，应继续调用 `get_note(note_id=..., detail="full")`，阅读完整正文后再回答；不能把查重摘要、任务完成摘要或核心洞见当成已读取完整笔记。只有用户明确要求简短总结/核心要点或仅查询状态时，才按该范围使用摘要。已有笔记命中时也遵循此规则。

`full` 完整图文正文免费可用。章节速读/思维导图的权限提示只针对那些独立视图，不代表完整笔记受限；旧客户端若返回容易误解的提示，先核对当前工具 schema 并尝试已提供的 `get_note(detail="full")`，不要索取升级或绕过权限。正文按 Markdown 返回，其中图片引用不等于宿主已加载图片；是否能显示或进一步查看图片取决于真实地址、访问权限和宿主能力，不声称看过仅引用但未读取的图片。

依据完整笔记回答原问题，不必在用户只要解释时把整篇正文贴满聊天。正文中没有的事实/时间戳不补造。输出路径只使用工具明确返回、用户已配置或已验证存在的位置；如用户要求保存到 Obsidian，先确认导出路径及图片处理方式，不自动安装插件或改 Vault 设置。

首个成功结果后，说明今后的使用方式：直接发送视频链接或客户端本机上的文件/目录；Agent 会检查连接，并在授权范围内尝试启动知影。通常无需重复配置，但需要电脑可用、客户端运行以及所选模型服务有效。
